# Faster retrieval with preserved task outcomes

The frozen candidate retained **the same eight official solves out of ten**.
It completed the cohort **29.16% faster than the previous Jevgrep cohort**, with
0.97% fewer Sol tokens and 1.87% lower Sol cost. Against the fixed no-Jev baseline,
it was **12.70% faster, 29.97% cheaper, and used 41.51% fewer Sol tokens**.

The [machine-readable report](speed-2026-09-28.json) contains every task,
archive identity, receipt hashes and matched metrics. The
[previous cohort](relevance-threshold-2026-09-27.md) remains a separate result.
All first attempts, including unresolved Matplotlib and Pylint tasks, count.

## What changed and why

Source validation now occurs once immediately before each HTTP attempt or
cached-answer return. Retrieval still serializes those checks, and retries still
check freshness. Removing a duplicate initial read reduces local work without
allowing cached results to bypass changed source or ignore rules. Binary detection
uses a native regular-expression scan with the same byte exclusions.

The earlier ignore-rule identity cache is included through v0.4.2. The candidate
uses TypeSafe's native endpoint for Jev; Sol still uses Vercel Gateway. Provider
choice, local optimizations and sampling all contribute to the measured result;
this cohort does not isolate their individual effects. Existing users' saved
provider choice is unchanged. The exact public retrieval skill is unchanged.

## Experiment findings

| Strategy | Evidence and decision |
| --- | --- |
| Reuse unchanged ignore rules | Recorded replay fell from 82.6 s to 16.7 s with the same output. Fresh identity checks and mutation tests preserve ignore changes. Shipped separately in v0.4.2. |
| Reuse compiled rules after rereading | One isolated replay was slower (108.3 s versus 82.6 s). Not selected. |
| Lower provider concurrency from 32 to 8 | Fewer HTTP failures but slower (29.0 s versus 24.2 s), with incomplete discovery in both diagnostic runs. Kept 32. |
| Defer rich previews until admission | Matching replay output, but no clear incremental live-task gain. Preserved as a deferred experiment; absent from this candidate. |
| Native binary scan | About 6.3× faster in the scan microbenchmark; about 5% faster in alternating full-file reads. Retained, without claiming that microbenchmark gain for whole tasks. |
| Validate once per attempt/cache return | Matching 365-request replay completed in 10.46 s. Cache-mutation falsification and queue/retry freshness tests passed. Retained. |
| Native TypeSafe route | Same-query diagnostic: median 140 ms versus Gateway 330 ms; search 34.3 s versus 43.4 s. Native had no errors; Gateway recovered 64 internal 503s. Used for confirmation. |

Raw traces, replay inputs and retained experiment patches remain in ignored
`evals/runs/swebench/speed-research/`. They are research evidence, not alternate
product implementations.

## Limits and task variation

These are ten tuned Python tasks, with one first attempt per task. The small
aggregate token and cost differences from previous Jevgrep may be sampling
variance. The observations support this measured cohort, not a guarantee of
improvement for every task, language, provider or machine. The reconstructed
Docker runtimes retain pinned official source images and verified archived tools;
runtime reconstruction is recorded in each plan. Host emulation also affects
absolute times.

Requests and Matplotlib cost more than previous Jevgrep. Requests retrieved the
implementation and tests first, but Sol still searched broadly and performed
additional verification. Matplotlib took essentially the same time despite all
815 native requests succeeding (267 ms median, 500 ms p95). Its official
input-copying test remained unresolved, with no official pass-to-pass failures.
Healthy model latency alone does not remove local work or dependent discovery
rounds. SymPy and Pylint substantially reduced time and tokens; Pylint still did
not solve its task.

This completes the planned speed comparison. The adopted candidate preserves
all previous solves and aggregate token savings in this run; no more paid trials
are needed to report this result.
